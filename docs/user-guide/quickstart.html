TROJAN PROXY / v1.0.0

第一次部署：从下载到可用

命令在Linux服务器执行；只有SSH隧道命令在你自己的电脑执行。以下用example.com举例，请替换成自己的信息。

1 · 准备服务器

需要Linux/amd64、Docker Engine和Docker Compose插件、SSH登录权限。查看环境：

uname -m
docker version
docker compose version
sudo ss -ltnp '( sport = :80 or sport = :443 )'

架构应为x86_64。若80或443已有监听，先确定原应用的迁移方案；本项目会拒绝接管，不会帮你停掉原服务。无域名也必须保留443。

云安全组/主机防火墙需要允许你自己的SSH来源。配置公网HTTP/HTTPS时放行TCP80、443。不要将18090、18091、18092开放到公网；它们只供本机使用。若最终共享443且引擎仅回环，无需放行18443。

2 · 下载固定版本并启动

以下是一组命令。需要curl、sha256sum和unzip；缺少时使用自己系统的包管理器安装。运行Docker的用户须有相应权限。

mkdir -p ~/trojan-proxy-download
cd ~/trojan-proxy-download
curl -fLO https://github.com/dream-until-dawn/trojan_proxy/releases/download/v1.0.0/trojan-proxy-v1.0.0.zip
curl -fLO https://github.com/dream-until-dawn/trojan_proxy/releases/download/v1.0.0/trojan-proxy-v1.0.0.zip.sha256
sha256sum -c trojan-proxy-v1.0.0.zip.sha256
unzip trojan-proxy-v1.0.0.zip
cd trojan-proxy-v1.0.0/deploy
mkdir -p public
docker compose up -d --pull missing
docker compose ps -a

SHA256应显示OK；prepare应成功退出（Exited 0），三个服务control、admin-gateway和vpn-runner运行。prepare退出是正常情况，不是第四个常驻服务。首次启动未配置业务和VPN，公网IP的80显示默认网页，443保留但不提供HTTPS。

日后执行Compose命令都在这个deploy目录，并保持项目名trojan-proxy不变。不要混用仓库根目录的旧版docker-compose.yml。发行包已固定三个镜像摘要，无需自己构建镜像或填写密码环境变量。

3 · 创建唯一管理员

在服务器的交互SSH终端执行：

docker compose exec control proxyctl setup-token

终端显示一次性令牌，10分钟有效，不要重定向、截图或分享。如果过期且尚未绑定，可重新执行获取新令牌。然后在你自己的电脑另开一个终端：

ssh -N -L 18092:127.0.0.1:18092 -L 18090:127.0.0.1:18090 用户名@服务器IP

使用密钥时按自己的SSH方式追加-i /密钥路径。保持此终端运行。在电脑浏览器打开http://127.0.0.1:18092，输入令牌、设置至少16字节的强口令，使用手机验证器扫描二维码或录入密钥，再填写验证码完成绑定。

务必离线保存恢复码。没有默认账号、注册入口或邮箱找回；不要把口令、验证器密钥和恢复码发给任何人。手机和服务器时间应自动校准，验证码不能重复使用。

完成后初始化端口自动关闭。通过同一隧道打开http://127.0.0.1:18090，用口令和下一组验证码登录后台。没有域名也可长期通过隧道管理HTTP反代。

4 · 在后台配置域名与HTTPS

  1. 准备主域名example.com，将其A记录指向服务器公网IPv4；仅在IPv6真实可达时添加AAAA记录。
  2. 为后台添加proxy.example.com；如有应用，再添加app.example.com。全部可以指向同一IP。使用直接DNS解析，避免仅支持HTTP的中间代理阻断原生Trojan。
  3. 确认公网TCP80和443可达、系统时间正确、DNS生效。
  4. 进入“系统设置”：主域名example.com；附加域名逐行填proxy.example.com、app.example.com；证书来源选“自动申请”，填写可接收通知的邮箱。
  5. 管理入口方式选“独立域名”，填写已登记的proxy.example.com；其他网络项先保留默认。
  6. 勾选变更确认，生成候选。待证书就绪，点击页面提供的新入口。
  7. 在新HTTPS入口重新用口令和下一组验证码登录，再到“系统设置”点击“确认此入口与设置”。

候选只有5分钟有效。超时会恢复旧入口，保持SSH隧道即可重新尝试；不要在快过期时反复点击确认。主站和已登记子域名证书自动管理；公网80随后跳转443（证书验证及爬虫声明等受控路径例外）。

这里仍未启用VPN。完成HTTPS后，可先按反代示例接入自己的应用。

5 · 启用Trojan和订阅

  1. 在系统设置中填写服务器“自身IP”：包含公网IP、实际出口IP和相关IPv6，逐行输入。这些地址用于阻止通过VPN访问服务器自身，不能填写Google等目标IP。
  2. 确认域名证书已就绪。在“Trojan VPN”确认并启用；独立模式默认引擎端口18443，使用此模式须自行放行TCP18443。
  3. 进入系统设置，勾选“网站与Trojan共享443”。生成候选并确认后，客户端公开端口变为443，引擎端口18443仍是内部端口。
  4. 在VPN页给电脑、手机分别命名并创建订阅，将只显示一次的URL保存到自己的Clash Verge / Clash Mi远程配置入口。
  5. 更新订阅并选中节点，开启客户端系统代理或适当的TUN模式，实际测试网站访问。
  6. 确认客户端节点为443且可用后，在系统设置勾选“关闭旧VPN公网入口，仅允许网关通过回环访问引擎”，生成候选并确认。此后引擎仅监听127.0.0.1:18443，云防火墙也可关闭18443。

改变敏感设置、创建或撤销订阅需要最近5分钟的双因素登录；提示过期时退出并重新登录。确认后的网络变更可能使VPN短暂重连，订阅URL不因此改变。共享443以主域名为Trojan的SNI；后台子域名用于管理，不要手动替换订阅里的节点域名。

6 · 自检与日常使用

  • 主域名网页正常、HTTP跳转HTTPS，后台只能在登录后操作。
  • 每个业务子域名指向正确应用，应用自身仍需登录，退出后不能查看私有数据。
  • 客户端更新订阅后节点是预期端口，实际代理访问成功；仅延迟测试绿灯不代替实际访问。
  • 后台“网站访问”和“VPN流量”均有采集状态；记录不是服务器全部应用的全局日志。
  • 立即生成一份私有配置备份，保存部署目录、Compose清单和恢复码。
