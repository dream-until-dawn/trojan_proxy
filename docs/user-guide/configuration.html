系统设置字段

以下列出页面名称和持久字段，供核对与自动化开发。日常不必编辑JSON或直接操作SQLite。

字段 / 页面含义与约束
domain
主域名		初始为空；小写ASCII/Punycode，不带https://、路径或端口；用作主站和Trojan身份。
domains
附加域名		最多20个，必须是主域名的唯一子域名；不接受*或与主站无关的域名。
admin_domain
后台独立域名		必须先列入附加域名；使用443根路径，不能同时设置管理路径。
admin_path
后台路径		例如/proxy；主域名HTTPS下使用。推荐新部署选独立后台子域名，减少应用路径冲突。
admin_port
后台独立端口		默认8007；1024–65535，不能与内控、文件、VPN及其他保留端口冲突。
vpn_port
Trojan引擎端口		默认18443；共享443时仍保留作后端端口，不要直接改成443。
shared_trojan_443
网站与Trojan共享443		默认关；需要主域名、可信证书和VPN管理。客户端导出端口改为443。
vpn_loopback_only
仅回环引擎		默认关；必须保留共享443，启用后引擎只监听127.0.0.1。
vpn_own_addresses
服务器自身IP		逐行填本机公网、出口及相关IPv6，最多64个；用于VPN出站防绕回保护。
vpn_resolver
VPN DNS解析器		默认9.9.9.9:53；IP:端口格式，IPv6例如[2606:4700:4700::1111]:53。
certificate_source
证书来源		none=无域名HTTP；automatic=自动申请；imported=手工导入。域名不为空时不能选none。
acme_email
ACME邮箱		可留空；填写时为规范邮箱，建议留能接收通知的地址。
imported_version
导入版本		由证书导入流程返回的64位版本摘要，不能任填服务器路径。
directories
公开目录绑定		最多100个；选择部署授权的根ID和根内相对目录，例如根public、路径.；不接受../或任意主机路径。

修改产生完整候选。涉及新入口时，从新入口重新登录再确认，旧入口在候选期限内保留。不要直接更改数据库格式；当前仅回环特性会将配置格式保护为8。

手工导入主域名证书

  1. 先在系统设置草稿中填写证书对应的主域名，证书来源选择导入。
  2. 进入证书管理，选择完整PEM证书链文件（含中间证书）和匹配的PEM私钥文件；需要最近五分钟双因素会话。
  3. 导入只校验并暂存，返回受控版本；返回系统设置，生成候选，再从候选入口重新登录并确认。

证书必须在有效期内、密钥匹配且由可信链签发；自签证书不是跳过验证的捷径。主域名使用手工证书时，到期需要重新导入和确认；不会偷偷切换为自动申请。附加子域名仍独立使用自动HTTP-01签发，因此其DNS和公网80仍须可达，不支持在后台设置DNS-01凭据或任意通配符域名。

示例一：app.example.com → 本机3000

  1. 业务服务先在宿主127.0.0.1:3000可访问。Docker应用可发布127.0.0.1:3000:容器端口，避免将业务原端口直接暴露公网。
  2. DNS将app.example.com指向服务器；系统设置中先登记该附加域名并完成证书/设置确认。
  3. “反向代理”新增：唯一ID如app、名称自定、监听443、域名app.example.com、路径/、类型反代、上游IP127.0.0.1、上游端口3000；保留前缀。
  4. 应用后访问https://app.example.com，验证登录、静态资源、API和退出行为。

上游只允许宿主回环IPv4/IPv6（例如127.0.0.1或::1）；填写的是IP和端口，不是http://URL、远程域名或Docker容器名。本版上游协议为HTTP，浏览器到网关可使用HTTPS；支持WebSocket转发。

示例二：端口8002 → 本机3001

新增规则：监听8002、路径/、类型反代、上游127.0.0.1:3001；HTTP模式可不填域名。自行放行云防火墙TCP8002，然后访问http://服务器IP:8002。需要TLS时勾选HTTPS并填写已登记且证书就绪的域名；访问https://app.example.com:8002。

同一个端口不能混用HTTP与HTTPS。22、Docker API端口、内控/目录/VPN端口等受保护，不能转发到管理内部端口或公开入口自身制造循环。普通公开路由属于匿名入口，目标应用的用户鉴权不会由本后台自动代替。

示例三：端口8001发布public目录

将要公开的文件放到发行包deploy/public，系统设置的目录绑定选择根public、相对路径.，给绑定起唯一ID。新增类型“公开目录”的规则，监听8001、路径/、选择该目录ID；根据需要勾选浏览列表，再自行放行TCP8001。

默认Compose只把deploy/public只读挂载到/srv/public/public。发布其他宿主目录，应修改这一挂载的来源并重建control；想增加另一个独立根，还要提供经过校验的部署配置public_directories及对应只读挂载。不要把密钥、备份、数据库或服务器根目录挂进公开区。

# compose.override.yaml：将默认public根改为自己的只读目录
services:
  control:
    volumes:
      - /srv/my-public:/srv/public/public:ro

Compose按相同目标路径覆盖挂载。更改前运行docker compose config核对结果，再重建control。后台不能越过显式挂载授权浏览任意目录，隐藏文件、符号链接和路径穿越有专门限制。

路径前缀何时需要“剥离”

请求/app/page，保留前缀时上游收到/app/page，剥离时收到/page。网关不会自动改写HTML/JS里的绝对资源地址、Location或Cookie Path。Next.js等应用若未按对应basePath构建，直接挂/app可能丢样式或串到其他应用。首次部署优先采用不同子域名＋路径/，各应用可以继续使用自己的根路径。

哪些设置必须在服务器修改

部署项位置与影响
镜像摘要deploy/compose.yaml；可用TROJAN_CONTROL_IMAGE、TROJAN_GATEWAY_IMAGE、TROJAN_RUNNER_IMAGE覆盖，但自行覆盖后不再等于本版核验组合。
CPU/内存/PID限制Compose的cpus、mem_limit、pids_limit；control默认256MiB、gateway/runner各128MiB，不能无限缩减而仍宣称通过原验证。
目录与专用数据卷Compose volumes。后台不接收任意宿主路径。
不可变部署配置镜像内/etc/trojan-proxy/proxy.json（源deploy/default.proxy.json）；version、control_port、data_dir、standard_ingress、public_directories等。常规部署不要修改；网页设置不会覆盖既有修订。
DNS与云安全组域名服务商/服务器控制台；后台不自动管理。

标准部署默认数据目录/data，内控18090及其后两个端口固定配合；默认admin_port=8007、vpn_port=18443是初始值，之后业务值由后台修订管理。没有通用“DOMAIN/TROJAN_PW”环境变量配置入口，那是旧版方式。
