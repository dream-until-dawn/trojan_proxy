启动后，主要配置在后台完成

本页是新增需求的可行性讨论与拟实施契约；不是已交付功能清单。现有管理员终端初始化、只读 JSON 部署配置尚未迁移。

总览开发计划架构

1. 部署体验可行，保留清晰的宿主机边界

推荐交付预制 Compose 发布包：用户获取发布文件后执行一条 docker compose up -d --pull missing，自动拉取固定摘要镜像并启动，不编译、不填写业务 JSON、不先执行交互式 install.sh。发布文件提供默认值和数据卷；停止/重建保留配置。该命令是交付目标，当前阶段性 Compose 不能当作最终安装包使用。

“一条启动命令”可以保留 control、gateway、vpn-runner 的权限和故障隔离。若必须是单镜像、单个 docker run，也可通过容器内监督进程实现，但要重新验证信号传递、子进程权限、健康判定及故障隔离，不能简单把现有三服务拼在一起。本轮推荐 Compose，不将单容器视为已确认决策。

首次启动不需要域名或管理员密码环境变量：自动生成主密钥和数据库，只开启 loopback 初始化入口；80 提供默认欢迎页，443 保留。先检查并实际绑定 IPv4/IPv6 的 80/443，任何外部占用都提示并停止本次启动，不停止冲突服务。标准端口不自动避让；后台候选端口按既有约定从 8008 向下选择并显示最终值，已有实例升级保留其端口。

  1. 通过复制的 SSH 隧道命令打开浏览器初始化向导。一次性初始化令牌由受限本机命令读取，不写普通容器日志，不放 URL；有短时过期、一次使用及并发抢占保护。
  2. 在网页设置强口令、绑定 TOTP，确认离线恢复码已保存。事务成功后关闭初始化能力；已初始化的数据卷即使重建也不得重新注册管理员。
  3. 进入后台选择无域名 HTTP 或填写域名、ACME 联系邮箱及证书来源；后台展示 DNS/端口可达性检查及中文修复步骤。
  4. 证书就绪后再开启公网 HTTPS 后台及 80→443；无域名仍通过 SSH 管理。失败时保留 SSH 入口及原有有效配置。
  5. 在后台管理路由、目录发布、Trojan、客户端导出与统计。主机目录、云安全组和 DNS 的实际修改由所有者完成，后台提供检查和操作说明。

启动阶段增加受限初始化协调器：只负责数据目录/共享 socket 的权限准备和完整启动/失败收尾，不给 Web 服务 root 权限，不挂 Docker socket。发布探针须证明实际 bind 失败无半启动业务实例，并能从失败状态安全重试。

3. VPN 目的 IP、流量和网速：滚动 30 天

默认记录协议、实际出站目标 IPv4/IPv6、目标端口、TCP/UDP、时间桶、上传/下载有效载荷字节及连接数。上传方向为客户端→目标，下载为目标→客户端；不含外层 TLS、链路重传等开销，因此与网卡/云账单不等同。不记录请求正文、URL、口令及浏览内容。

后台提供全局和按目的 IP 的流量排行、时间范围筛选、上下行曲线及实时网速。拟定实时每 2 秒更新，仅留内存短窗口；历史按 1 分钟保存全局及目的 IP 聚合，保留最近 30×24 小时，平均速度为时间桶字节增量÷实际秒数，峰值注明为采样峰值。没有采集数据的间隔显示缺失，不能伪装成零速。长期连接按时间桶持续结算，不能等连接关闭才记录。

采集首选固定版本引擎的受限连接跟踪/出站适配接口，不开放通用公网 Clash API。已核实 sing-box v1.14.4 存在 Router.AppendTracker 和 TCP/UDP 跟踪接口，但路由元数据中的 DNS 候选地址不等于最终拨号地址；必须通过探针证明实际成功出站 IP 的归属、多 IP 回退、UDP 多目标及计数完整性，必要时在 direct 出站拨号/包读写处增加受限观测适配。当前最小引擎拒绝 experimental，不能直接打开通用 API 就宣称满足要求。

独立 traffic.db 保存分钟聚合，不生成永久原始连接日志。队列、活跃目标数、批量大小、分页及磁盘空间均有上限；过载时保留全局汇总并明确标记目的明细缺口，不能阻塞代理或静默丢数据。跨进程重启用实例标识/序号避免重复累计，崩溃损失窗口明确显示；统计服务不可用不影响数据转发。

保留契约：查询始终过滤早于当前 UTC 时间减 30 天的桶；启动时及至少每小时分批删除过期数据，同时维护索引、清理 WAL 和可复用空间。开放连接的旧桶同样过期。不保留超期日报、IP 列表或日志副本；默认备份排除统计库及其 WAL，导出的统计由所有者自行保管。删除为应用层保留边界，不承诺抹除外部磁盘快照。检测到时钟异常时标记统计异常，恢复时先清理再提供查询。

前置探针上限 30 分钟：受控 TCP/UDP 哨兵发送已知字节量，验证真实目标、方向、跨桶长连接、IPv6/域名多地址回退；模拟断连/重启/过载/磁盘满/统计库锁定。先量化误差和开销，再冻结采样预算。移除计数方向保护、30 天过滤或清理条件分别应触发对应断言失败。

4. 标准端口的默认欢迎页

80/443 没有命中已配置业务规则时显示简洁页面：欢迎访问 qin-xin.top，下方仅一个绿点或红点及“状态正常 / 暂时不可用”的无障碍说明。域名取已验证配置并转义；无域名使用“欢迎访问”及已确认的服务器 IP。未知 Host 仍拒绝，不反射任意 Host、不触发任意域名签发。页面不展示 VPN、反代、管理入口、版本、CPU、内存、地址清单或内部错误。

公开状态仅表示公共网页服务可用性，与 VPN 启停、目标连通性及后台登录状态无关；详细系统状态放鉴权后台。绿点代表欢迎页服务正常，红点用于仍可返回维护页的公共 Web 退化；整机/网关不可达时无法承诺显示红点。页面内置样式，无第三方资源、追踪脚本或公开诊断 API。

路由顺序：ACME 验证 → 系统保留路径（robots.txt 等）→ 已配置业务规则 → 欢迎页兜底。已命中的业务规则返回 404/502 时保留其响应，不掩盖为欢迎页；后台端口不使用公共欢迎页兜底。无域名仅 80 提供页面、443 保留；证书就绪后 80 跳转 443 显示页面，验证路径例外；证书未就绪/失效不提供伪 HTTPS 或隐式降级。

正确文件名为 /robots.txt，在本项目管理的每个 HTTP/HTTPS 公开站点及自定义端口提供：

User-agent: *
Disallow: /

统一由网关提供此保留路径，业务规则不能覆盖；HTTPS 就绪时 HTTP 站点的 robots.txt 也直接返回该声明。ACME 验证仍可直接访问，不受 robots 策略或鉴权拦截。为默认页、后台、公开目录和反代响应添加 X-Robots-Tag: noindex, nofollow, noarchive, nosnippet；自有 HTML 同时添加 robots meta，不发布 sitemap。声明不爬取适用于全部爬虫，但 robots 协议依赖对方遵守，不能保证不访问或 URL 永不被收录，也不能替代后台鉴权。
