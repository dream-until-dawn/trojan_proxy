网站访问与VPN流量分开管理

开发计划验收差距

已确认契约

所有经过本项目HTTP/HTTPS入口的请求全量记录，不抽样，包含静态资源、重定向、错误请求和后台/探针请求。白名单仅用于可信来源分类与保留期，不拦截其他IP；支持IPv4、IPv6和CIDR。当前白名单来源滚动保留7天，其余30天，名单变更立即按当前规则重新分类和清理历史。

字段为请求时间、实际TCP连接IP、域名/入口端口、方法、原始路径、状态码、耗时及HTTP请求/响应正文的实际字节数。不采集查询参数、请求/响应头、Cookie、Authorization、验证码、正文。应用若把秘密放入路径，仍需自行避免这种URL设计。VPN代理的目标IP/流量/网速仍在独立“VPN流量”页，不与网站访问计数混加。

模块与数据流

  1. Caddy原生访问日志无抽样；写盘前用过滤编码器删除所有请求/响应头及TLS详情，URI在编码阶段去除查询和绝对URL的authority。所有HTTP服务启用，包括默认页/robots/不匹配Host；入口端口由受信任logger名称携带，不信任X-Forwarded-For或其他来访者可伪造的头。
  2. 脱敏日志位于现有caddy-data专用卷/data/access，权限0600；control从/caddy-data/access只读采集。每整点独立定时轮转，另有1小时间隔/16MiB轮转；活动文件及8份备份合计约144MiB上限、约26小时以内的原始缓冲，早于7天最短明细窗口清理。它是短暂交接缓冲，不作为长期访问档案。
  3. 新internal/webaccess模块独立access.db（主库1GiB上限，WAL及轮转文件额外占空间，不能把主库上限称作总磁盘硬配额），不改认证/规则/VPN数据库。文件身份与首行指纹、读取偏移及事件在同一事务中保存，处理轮转/重启和不完整尾行，避免重放或跳过。白名单配置单独持久化并带修订；查询按当前IP/CIDR动态分类，边界过滤与定期物理删除共同落实7/30天。
  4. 独立后台API，读取需要认证；修改白名单需要最近五分钟双因素验证和配置修订。新“网站访问”页提供总量、可信/非可信、状态、字节和分时统计，以及按时间/IP/域名/路径/状态分类筛选的分页明细；名单在页面配置。现有“流量记录”改名“VPN流量”。

可靠性和明确边界

单请求在HTTP处理完成后入日志；WebSocket等长连接在结束后形成完整记录。TLS握手失败/无效报文未形成HTTP请求不计为网站请求。HTTP字节不是含TLS的网卡流量。统计库设置容量上限与短锁预算；写满/采集失败不能阻断公开服务，后台必须显示暂停/延迟/可能丢失，不能把缺数据称作零访问。全量无抽样不等于物理故障或超出有限缓冲仍能保证零丢失。

原始缓冲必须定时轮转，即使低流量也不能将旧可信IP留在活动文件数周；该行为需真实网关验证。默认白名单为空，不擅自把服务器回环/当前操作者IP设为可信。访问数据和短暂日志不进入公开运维证据、配置备份或VPN导出。白名单与访问库同卷持久化，普通容器升级保留；当前配置恢复包不包含访问库或白名单，冷恢复后需在后台重新设置，默认空名单按30天分类。未采集时期不补造访问历史。
