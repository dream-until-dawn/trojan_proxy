验收计划部署边界恢复设计

发布状态

当前为验证中的候选版本：三个镜像已通过完整CI门槛并完成匿名拉取，Compose固定到不可变摘要。真实80/443交接和公共自动证书已通过，正式版本仍待24小时长稳。镜像清单与证据。支持 Linux x86_64、Docker Engine 和 Compose v2。DNS、云安全组及宿主机目录挂载仍需所有者处理。

首次启动

从当前候选Compose下载到空部署目录并命名为compose.yaml，再执行以下命令。80/443 必须空闲；发现占用时预检退出，不杀占用进程。准备容器退出码为0是正常结果。

mkdir -p public
docker compose up -d --pull missing
docker compose ps -a
docker compose exec control proxyctl setup-token

最后一个命令必须在交互 SSH 终端执行。令牌十分钟有效，不要重定向或发给他人。在自己的电脑另开终端建立隧道：

ssh -N -L 18092:127.0.0.1:18092 -L 18090:127.0.0.1:18090 用户@服务器

打开 http://127.0.0.1:18092，设置强口令、绑定验证器并离线保存恢复码。完成后初始化端口关闭，使用 http://127.0.0.1:18090 登录。无域名时持续通过此隧道管理。

在“系统设置”填写域名、证书来源、管理入口方式（独立HTTPS端口或网站HTTPS路径，例如/proxy）、VPN端口、自身地址与解析器；“证书管理”用于导入和查看证书状态。添加域名之前先把DNS指向本机；自动证书需公网TCP80/443可达。候选配置保留旧入口五分钟；打开新入口重新双因素登录并确认后完成切换。失联或不确认会撤回。导入证书先暂存，选定版本并确认设置后生效。

反代支持域名、路径和自定义端口，宿主机服务可填127.0.0.1。目录只可选择已明确挂载的只读根和相对目录；默认根对应发布目录下的public。新增宿主机根必须修改Compose挂载并重建，后台不能访问任意宿主机路径。Trojan启用前需可信证书、正确自身地址，以及云安全组放行其TCP端口。

配置与认证的一致性备份

docker compose exec -T control proxyctl backup
docker compose cp control:/data/backups ./private-backups

首条命令输出归档路径、大小和SHA256，不输出秘密。将SHA256单独保存到可信记录；备份文件包含认证材料和主密钥，必须私有保存。备份失败不得把不完整归档当作成功结果。该备份包含部署描述、配置修订和认证状态，明确不含30天流量库。

此归档也不含证书文件和ACME缓存。升级前应保留certificates、caddy-data持久卷及公开目录；需要迁移到新主机时另行私有备份这些卷，或在SSH隧道中重新导入/签发证书后才启用HTTPS/VPN。仅恢复控制归档不能保证立即恢复HTTPS。删除数据卷会丢失认证和证书，日常停止请勿使用 down -v。

遗失验证器或口令

尚有离线恢复码时可在登录页使用一次。全部丢失则在自己的SSH交互终端执行：

docker compose stop control
docker compose run --rm --no-deps --entrypoint proxyctl control admin-reset
docker compose up -d control

重新设置口令、绑定全新TOTP并保存全新恢复码。运行中的控制进程会阻止重置，避免旧内存会话继续有效。重置不替换主密钥、VPN口令和路由。

空卷冷还原

用于灾难恢复，不能覆盖正在使用的数据卷。目标部署须沿用归档deployment.json中的不可变部署参数、受信任挂载和防护基线；DataDir可以改变。默认部署之间可直接使用相同预制配置。自定义部署请从自己的私有备份提取deployment.json，核实其挂载后作为配置提供给工具，不要发到公开仓库。先让prepare整理空专用卷，但不启动control；把私有归档以只读挂载方式加入一次性维护容器，例如以下维护覆盖文件：

# recovery.compose.yaml；将路径换成自己私有保存的归档
services:
  control:
    volumes:
      - /私有路径/backup.tgz:/restore/backup.tgz:ro
docker compose run --rm --no-deps prepare
docker compose -f compose.yaml -f recovery.compose.yaml run --rm --no-deps --entrypoint proxyctl control restore --archive /restore/backup.tgz --sha256 从可信记录取得的完整摘要
docker compose run --rm --no-deps --entrypoint proxyctl control admin-reset
docker compose up -d

冷还原后旧管理凭据被锁定，必须SSH重绑后才能启动control。确认新主机域名、自身IP、证书及目录挂载，再启用业务。若还原因中途磁盘错误留下recovery-required，请保留证据并使用另一个空专用卷重试，不删除保护标志绕过鉴权重绑。

升级与回退

升级前生成一致性备份，记录当前镜像摘要并保留证书卷。新版本先完成完整门槛；切换后验证可信TLS、未认证拒绝、真实代理流量及其他服务未受影响。设置库最低schema3、显式HTTPS规则最低schema4、管理路径最低schema5；旧程序不能读取更高格式。回退须先用兼容的新程序撤回不兼容特性并停止control，再持有独占维护锁执行proxyctl downgrade-format --target-version 4（仅当管理路径已撤回、没有候选/准备修订时）；若仍有HTTPS规则不能降至3/2。不要直接回写SQLite版本或覆盖旧认证数据库，使已用恢复码复活。
