引擎二进制扫描与最小构建

总览VPN实施

当前结果

受限Trojan引擎已通过Linux源码与最终Linux二进制扫描，均未发现已知漏洞；替换后TCP/UDP、认证、地址限制、DNS改变、证书回退和进程/容器恢复重测通过。Caddy同版本受限构建的Linux源码及最终二进制也已扫描归零，HTTP-01/续期、缓存发布、80/443和旧快照安全策略迁移均复测通过。远端仍未升级，待完整部署门槛通过后再切换。Trojan结果及限制 · 网关结果及限制。

部署暂停原因

2026-11-11补充对候选官方sing-box 1.14.4镜像内二进制执行govulncheck v1.9.0，报告27项漏洞的相关符号，涉及10个模块及Go1.26.10标准库。二进制扫描不等同于证明这些路径均可由当前Trojan配置利用，但不能直接套用控制服务源码扫描的零可达结论。

因此已在SCP上传阶段停止本轮并行部署，尚未运行远端升级脚本。只读复核表明三个部署文件仍匹配M4基线，控制服务、Caddy和旧Trojan的容器ID与启动时间未改变。VPN18443仍空闲。现有服务继续运行。

修复方案与边界

  1. 保持独立runner及协议适配边界；在单独engines/trojan Go模块内构建最小CLI，固定官方源码v1.14.4及校验和。
  2. 仅注册Trojan入站、direct出站和UDP DNS，不导入通用发行CLI与默认全协议注册器；拒绝实验后台、服务、端点和证书提供者配置。
  3. 使用Go1.26.11并按扫描报告升级实际构建需要的依赖，固定版本及go.sum；同时进行源码可达与最终Linux二进制扫描。
  4. 替换引擎后重跑真实TCP/UDP、地址限制、错误认证、证书轮换/回退、进程退出和容器重启。通过后才重新打包并行部署。

Trojan和网关的受限构建已通过当前扫描与真实探针；完整离线包仍需部署前自动门槛绑定实际程序与镜像。根项目与引擎分模块，现有控制面接口和SQLite格式保持一致。

许可证和交付

根项目继续使用原MIT许可证。独立引擎链接GPL-3.0-or-later的sing-box，engines/trojan按GPL-3.0-or-later交付，保留上游许可、来源、精确依赖与构建说明；发布引擎镜像时同时提供对应源码和依赖清单，不把整个根项目改为GPL。

依据与复现

govulncheck -mode=binary <镜像内sing-box>。例如Brotli报告涉及构造压缩流的内存消耗；上游注册器可核实通用发行构建包含的功能范围。

网关快照迁移与同源设置

持久修订新增gateway_settings指纹，包含编译版本及部署设置。旧快照或设置变化通过协调器生成新修订，保留反代规则与VPN密文；迁移拒绝时恢复旧快照。真实Caddy测试确认h1/h2策略不会在独立重启后被旧JSON覆盖。控制服务与runner读取同一份部署配置，避免端口、解析器和服务器自身地址漂移。

命名卷的空卷自动复制会覆盖预设权限，探针使用volume-nocopy保持所有权；生产绑定目录不采用该复制机制。新的失败日志合并stdout/stderr，避免把空日志误当作无错误。

控制面依赖升级

首次完整离线包门槛拦下控制面旧x/crypto版本的模块级报告；此前源码调用图判定相关SSH/OpenPGP路径不可达。为统一交付依赖，升级到同一修复版本，并增加由旧v0.48.0生成的固定假口令散列测试，正向验证已有账户兼容、反向验证错误口令拒绝。最终部署仍须从实际离线包重新扫描全部程序。
