结构化路由与受控应用

总览计划

规则契约

每条规则有固定ID、名称、监听端口、Host、路径前缀和目标类型。首版反代上游限定宿主机回环IP和显式端口，拒绝内控、SSH、Docker控制端口及形成自循环的目标。路径按段匹配，/app不匹配/apple。最长前缀优先；精确Host优先于空Host兜底；重复匹配拒绝。

公开目录只选择已挂载的目录ID，真实文件打开由受限文件模块完成。页面不接受Caddy原始JSON、脚本或任意宿主机绝对路径。规则中不保存管理员或VPN凭据。

从阶段性后台到完整入口

当前80/443仍由旧Trojan容器持有。阶段性反代仅允许自定义端口，不尝试抢占或停止其他监听；最终统一接管后才开放80/443业务规则。创建规则必须显式展示公开访问范围，默认没有业务登录保护。

Caddy控制接口采用共享Unix socket，权限0660、组10001，仅控制服务可访问，不暴露2019。应用完整生成配置时始终保留后台8007、TLS绑定和管理socket。数据库保存desired/applied修订；Caddy的原子加载保证坏配置保留旧网关，协调器负责跨组件恢复。

验收门槛

正向：本机HTTP服务、WebSocket、自定义端口、Host/路径分流。负向：保留端口、重复规则、元数据地址、管理接口、自循环、错误路径。应用失败必须保留旧路由；进程重启按数据库恢复。这些适配器已通过真实Caddy生命周期验证并部署阶段性管理界面。目录原始URI头由网关覆盖设置，索引使用相对链接；修复后的目录规范跳转已实测。审计与修订在同一SQLite事务提交，最多保留10000条且不记录原始引擎配置。实测记录。80/443完整接管另行验收。
