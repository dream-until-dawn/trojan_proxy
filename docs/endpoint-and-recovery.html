同域名不同端口的鉴权边界

浏览器来源包含协议、域名和端口，而 Cookie 的隔离边界不包含端口。为避免后台凭据被自动发送给同域名其他服务，管理员令牌不放 Cookie、URL、localStorage 或 sessionStorage，仅保留在页面内存，用 Authorization 头提交；刷新或关闭页面后重新登录。

单管理员强口令 + TOTP 不变；API 严格校验允许的来源，拒绝跨来源写入，不开启通配 CORS。前端采用严格 CSP、静态资源同源与输出转义，不允许自定义脚本。来源隔离不能抵御后台自身 XSS，因此令牌短期有效并支持服务器端撤销。

无域名模式下后台仍只经 SSH 隧道访问，不因这个域名配置开放明文公网登录。SSH 本地来源显式配置，和公网来源采用同一身份模型。

配置应用与恢复的当前实现

新增 internal/runtime 协调器：验证两个组件 → 保存 pending 日志 → 顺序应用 → 保存 applied；任何失败返回原始原因并补偿恢复旧快照。回滚采用独立的 15 秒清理上下文，调用方取消请求不会直接取消恢复；恢复失败保留 pending 并拒绝继续写入。

新增 internal/storage SQLite 日志：WAL、FULL 同步、schema version 检查，不覆盖既有状态。测试覆盖 prepared、网关应用后、VPN 应用后各阶段恢复；还使用子进程 os.Exit(17)，故意跳过数据库关闭和 defer，再重新打开数据库验证已提交 pending 可恢复。

以上SQLite重开、异常退出与schema拒绝测试已在目标Linux服务器通过，结果证据。当前组件状态由测试适配器模拟，不能据此声称真实 Caddy/VPN 跨组件恢复已验收。下一步接入实际适配器并比对运行配置摘要；单进程协调锁也尚未替代部署实例锁。
