将已有40GiB云盘空间纳入根文件系统

开发计划进展

目标与边界

用户授权先备份及验证，再扩入剩余约10GiB，尽量不影响服务及原长稳。只操作/dev/vda的第3分区和其ext4文件系统，不扩大云盘规格，不格式化、不移动起点、不重启或停止业务，不缩减根卷。演练显示起点415744保持，大小从62498783增至83470303扇区；两个引导分区与全部UUID必须不变。

备份与执行顺序

  1. 读取当前服务、内核、挂载、分区和长稳基线，运行growpart --dry-run；检查是否存在存储错误。
  2. 使用现有云CLI尝试创建当前40GiB系统盘快照并等待成功；不读取或输出云凭据。快照为在线崩溃一致性，不冒充全部应用事务一致性。分区表、原始GPT及必要引导元数据另存服务器私有目录并校验散列，取回本地私有副本；控制应用使用已有在线一致性备份。
  3. 仅在备份已验证、根挂载与分区身份一致、无其他分区改动时执行growpart；核对内核识别到新边界后，执行resize2fs /dev/vda3，不使用-f跳过保护。
  4. 验证磁盘与文件系统容量、GUID/UUID/起点、内核无新增存储错误，实际读写/哈希，全部服务身份/启动/健康、HTTPS和VPN、原长稳PID/起点/源码及累计失败。

失败立即停在当前阶段，不盲目重复写入、不在线运行e2fsck、不自动重启。文件系统扩展后不能直接恢复旧的小分区表，恢复需基于云快照与恢复环境；不执行自动缩容。
